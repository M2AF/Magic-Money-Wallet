## Supported-interface gaps to resolve before in-wallet mainnet routes

1. **Inbound quote:** a versioned IOG/Circle interface for the current Ethereum/Arc → Cardano minimum, charged or estimated fee, recommended `maxFee`, quote validity and failure/recovery when the cap is too low. [Circle's published xReserve OpenAPI](https://developers.circle.com/openapi/xreserve.yaml) has a withdrawal preparation endpoint, but no deposit quote endpoint; see [gate 2 research](XRESERVE-GATE2-RESEARCH.md).
2. **Inbound self-submit:** if the Portal FAQ's fee-cap recovery applies to independent wallets, its documented trigger, transaction builder/schema, signing validation rules, fee funding and idempotency. [Source: IOG minting FAQ](https://usdcx.iog.io/faq).
3. **Outbound Cardano burn:** versioned IOG/Midgard request/response schemas and access terms, the validator/datum/redeemer rules needed to check unsigned CBOR, signing/submission ownership, operator signatures and a burn-to-Circle status mapping. [Source: IOG burning FAQ](https://usdcx.iog.io/faq); [Circle xReserve OpenAPI](https://developers.circle.com/openapi/xreserve.yaml).
4. **Current burn finality:** reconcile 1,620 confirmations/about 9 hours in the [FAQ](https://usdcx.iog.io/faq) with 400 blocks/2–4 hours in the [Portal terms](https://usdcx.iog.io/docs/USDCx_portal_terms_of_use.pdf).
5. **Crosschain DEX route:** a supported DEX Direct API, if third-party wallets may use it; otherwise compose the wallet's own verified xReserve inbound path with the existing Minswap Cardano swap, tracking both stages independently. [Source: DEX Direct FAQ](https://usdcx.iog.io/faq).

## Recommended sequence for Claude

1. Preserve and review the live [testnet QA record](XRESERVE-TESTNET-QA.md); no further testnet transfer is needed for the same success case.
2. Close the testnet executor's known persistence windows before considering mainnet execution: deposit broadcast before tracking save, prepared deposits held only in memory, and desktop tracking writes in place. The windows are documented in the [QA record](XRESERVE-TESTNET-QA.md).
3. Keep mainnet inbound and outbound disabled while the supported-interface gaps above remain. Add no static fee or minimum based on the Portal's frontend text or historical on-chain allocations.
4. Once a supported inbound quote/recovery contract exists, adapt the already verified deposit, proof and tracking modules to mainnet; then compose the Cardano DEX leg using gate 1's existing quote, pre-signing validator and order tracker. Handle “minted USDCx” and “DEX filled” as different milestones.
5. Treat Cardano → Ethereum burns as a separate gate requiring IOG's published builder and attestation support. The [official Portal](https://usdcx.iog.io/bridge) remains the external path until then.

This note records public Portal UI/FAQ behavior as observed on 2026-09-30. It does not claim that the Portal's internal endpoints are supported for third-party use.
